# 内置 Starter 素材契约

简体中文 · [English](STARTER-MEDIA-CONTRACT.md)

本契约把随应用交付的 Starter 视频、语音、音效、图像、图标、本地化与数据文件变成
可重复检查的库存。它证明“这些字节与这些声明一致”，不证明素材来源真实性，也不替代
所有者、法律或媒体权利审阅。

## 当前状态

- 清单精确覆盖 198 个可交付文件，构建不需要 Seedance、TTS 或任何供应商凭证。
- 当前回执是 `PASS_WITH_PENDING / INTERNAL_PREVIEW_ONLY`。
- 权利审阅通过 0/198；无障碍审阅通过或不适用 3/198；包级许可证仍待所有者确认。
- 提供商不可用时，应用仍可降级到本地文字、静态图形和已有音频。
- 清单明确声明不含 API Key、任务正文、个人路径，也不需要运行时联网。

这些数字是当前仓库状态，不是对公开发行的承诺。修改任何受清单管理的文件会改变
SHA-256，并使该文件既有权利与无障碍审批回到待审；工具不会静默继承旧结论。

## 四层证据

| 层 | 自动检查能证明什么 | 不能外推什么 |
| --- | --- | --- |
| 源目录 | 没有未列入清单的文件、隐藏元数据、符号链接或陈旧归档 | SwiftPM 缓存已经净化 |
| 当前构建产物 | 当前调试／发布资源包与源清单逐文件一致，只额外允许已校验的 SwiftPM `Info.plist` | 旧构建目录也一致 |
| 当前 `dist` | 当前打包应用只含清单允许的 198 个文件和清单本身 | `/Applications` 中的应用已经更新 |
| 已安装应用 | 只有对实际安装版本的独立检查才能确认 | 源码或 `dist` 通过不能替代安装验证 |

在零授权环境中不得为了补最后一层而替换应用。该层应回执“待验证”，其余三层仍可独立
通过。源码清洁、构建产物清洁与安装应用清洁必须分别表述。

## 本地检查

确认清单仍与源资源一致：

```bash
python3 scripts/refresh-starter-media-manifest.py --check
```

输出隐私安全、机器可读的当前状态：

```bash
python3 scripts/audit-starter-media.py --json
```

执行公开候选严格门；当前预期退出码为 3，而不是成功：

```bash
python3 scripts/audit-starter-media.py --strict --json
```

运行丢失文件、篡改、额外归档、私有路径、重复 ID、伪造审批以及审批重置矩阵：

```bash
./scripts/run-starter-media-contract-smoke.sh
```

生成器的 `--write` 只负责重新盘点字节与保留未变化文件的真实人工元数据。新文件或变更
文件必然回到待审。最终许可证、证据引用与批准人必须由项目所有者依据真实授权填写。

## 贡献与发行边界

贡献者可以补充准确的来源、作者／提供者、许可证或授权依据、允许用途、署名要求、成年／
虚构状态、中英 alt 文本／字幕／声音说明、回退和审阅版本。不得把“由模型生成”“已付费”
或“哈希一致”当作可再分发许可。

公开发行仍必须同时满足[发行就绪状态](RELEASE-READINESS-STATES.md)与
[授权和权利边界](LICENSING-AND-RIGHTS.md)。本契约通过时只代表 Starter 清单自身可验证；
在最终 LICENSE、Developer ID、Apple 公证和所有者批准缺失时，项目仍是源码预览。
