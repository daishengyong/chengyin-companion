# 节目现场使用：交给 Codex 的完整主提示词

把下面整段复制给新电脑上的 Codex。录节目时不要逐字朗读，让观众看到 Codex 如何复述、规划并逐步执行。

```text
你现在是我的 macOS 桌面伴侣工程师、视频素材导演和安装可靠性工程师。请把“澄音 Companion”安装并验证好；如果我同时提供源码改造包，再基于现有工程完成一个我指定的小改造。不要只给建议，要按阶段实际检查、执行、验证，并持续用简短中文告诉我当前在做什么和为什么。

我的目标：
1. 先在这台 Apple Silicon Mac 上快速安装一个可用的 Codex 桌面伴侣；
2. 她平时以小动态头像陪伴，能切换半身和全屏；
3. 单击、双击、长按、拖拽、快速甩动和小游戏有即时反馈；
4. 只有 Codex 主任务真正完成并验证通过后，才播放一次任务庆祝；
5. 后续能替换角色视频、语音、提醒节奏和互动玩法；
6. 不读取或上传我的代码、Prompt、任务标题、路径和对话内容，不申请麦克风权限。

我可能提供以下文件：
- `Chengyin-Companion-*-macos-arm64-preview.zip` 或已解压的同名目录；
- `Chengyin-Companion-*-source.zip` 源码改造包；
- 我自己拥有权利的图片、视频或声音素材。

请严格按以下阶段推进：

阶段 0：安全盘点
- 定位我明确提供的安装包与源码包，不扫描无关私人目录。
- 检查 CPU 架构、macOS 版本、磁盘空间、包内 SHA256 清单、应用签名封装和关键文件。
- 明确告诉我这是个人预览包还是正式签名公证包；不得把 ad-hoc 签名说成正式发行签名。
- 检查现有 `~/.codex/AGENTS.md` 和 `~/.codex/config.toml` 是否存在，但不要输出其中的私人内容或 Key。
- 不覆盖已有 Codex notify；不读取 cookie、token、浏览器 session 或云端账号信息。

阶段 1：快速安装
- 优先使用包内 `Install Chengyin Companion.command`，默认安装到 `~/Applications`，不要求管理员密码。
- 安装器应保留已有 AGENTS 内容，只加入带 Chengyin 起止标记的完成事件规则；不得修改 config.toml。
- 启动应用，并运行 `Diagnose Chengyin Companion.command`。
- 验证主程序、视频资源、任务完成 helper、Codex 规则和运行进程。
- 首次被 Gatekeeper 阻止时，不绕过系统安全；清楚告诉我如何在“系统设置 → 隐私与安全性”中人工选择“仍要打开”。

阶段 2：基础体验检查
- 验证头像、半身、全屏三种模式。
- 验证单击、双击、长按松手、短拖、长拖、快速甩动和边缘吸附。
- 验证至少一个小游戏和一个生活提醒预览。
- 用应用自己的预览快捷键检查完成视频，但预览不能写入真实任务完成事件。
- 所有自动化测试事件必须设置 `CHENGYIN_EVENT_ROOT` 到新建临时目录。

阶段 3：源码与素材合同（仅在提供源码包时）
- 先读取项目 `AGENTS.md`、README、Package.swift 和与本次改造直接相关的文件。
- 盘点现有视频、音轨、声音清单、动作枚举、场景枚举和事件协议；报告数量、尺寸、时长、音轨和异常。
- 先给出最小改造方案：涉及哪些文件、复用哪些素材、增加哪些测试、如何回滚。
- 角色素材必须是明确成年（25+）的原创虚构角色；不得模仿明星、公众人物、演员、受保护角色或可识别真人。
- 一个 16:9 母视频尽量复用于头像、半身和全屏，减少重复生成；素材名与动作/事件名保持稳定映射。

阶段 4：我指定的小改造
- 在开始改动前，用一句话确认本次唯一目标，例如：“新增番茄钟结束后的击掌奖励”。
- 完成输入 → 即时反馈 → 视频/声音奖励 → 冷却与避免重复 → 自动测试的闭环。
- 保持任务完成、生活提醒、手动互动和小游戏事件彼此分离；不能把计时器、一次 Codex 回合结束或预览当成任务完成。
- 保留用户设置、关系记忆和内容包；更新必须可回滚。

阶段 5：新素材生成计划（只有我明确要求时）
- 先写角色 Bible、镜头合同、Prompt、负面约束、音轨要求、成本上限、权利来源和验收标准。
- 优先“角色母片 → 含视频输入的派生动作”；先做 1 条校准，不直接批量。
- 如果要调用 Seedance、Ark TTS 或任何付费 API，先给我展示模型、调用次数、分辨率、时长、是否含视频输入、预计 Tokens/费用和停止条件，然后停下来等我明确确认。
- 未得到本轮明确确认，不得调用付费 API，不得因为本机保存过 Key 就自行生成。
- 生成后记录任务 ID、资源包抵扣、输入权利、输出 SHA256、音轨、自动转写和人工审核状态；Key 不得写入项目、日志或节目画面。

阶段 6：验证与安装
- 运行项目规定的 release build、合同检查、事件 watcher、媒体解码、声音清单和完整 doctor。
- 测试事件只能进入临时目录，确认 live 事件目录数量没有变化。
- 构建最新应用并通过原子安装流程替换本机版本；确认运行进程来自新安装应用。
- 若任何必要检查失败，继续修复或明确报告阻塞，不得宣称已完成。

阶段 7：真实完成
- 只有以上目标实际完成、必要检查通过且本地安装验证后，主 Codex agent 才能在最终答复前发出一次真实 `task.completed`。
- subagent、预览、dry-run、普通问答、进度节点、失败或部分完成都不得触发。
- 最终给我一份简短交付单：安装位置、版本、改动内容、验证结果、回滚位置、素材权利状态和下一步最值得做的一个改造。

执行风格：
- 先复述目标和列出 5–8 个阶段计划，然后开始工作，不要连续抛很多问题。
- 对可安全发现的信息自己检查；只有涉及付费、发布、账号、权利不明或会改变方向的选择才停下来问我。
- 每次更新控制在 1–3 句话，让我在节目屏幕上能快速看懂进展。
```

## 节目中的追加改造指令

```text
在现有伴侣上增加一个 25 分钟专注计时器。计时中保持小头像安静；结束后自动展开到半身，播放鼓掌视频和一条不重复的鼓励语；允许暂停和取消；不得把计时器结束伪装成 Codex 任务完成；增加自动检查并安装验证。节目演示可以使用 20 秒测试配置，但产品默认必须保持 25 分钟。
```

## 如果只想安装，不改源码

在主提示词第一段末尾补一句：

```text
本轮只执行阶段 0、1、2、6、7；不要展开源码改造，也不要调用任何生成 API。
```
