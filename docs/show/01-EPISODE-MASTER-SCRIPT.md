# 第 1 期节目总稿：我让 Codex 给自己做了一个会庆祝的桌面伴侣

## 节目定位

- 形式：真人讲解 + 屏幕录制 + 伴侣即时反应 + 已生成素材拆解。
- 核心受众：已经使用 Codex、Claude Code 或其他编程智能体的程序员和 AI 重度用户。
- 建议时长：13–15 分钟。
- 画幅：16:9，建议录制 1920×1080；伴侣视频本身保持原始比例，不拉伸。
- 一句话价值：不是教观众再做一个聊天窗口，而是教他给 Codex 增加一个有生命感的“反馈层”。
- 看完行动：下载个人预览安装包；完成一次真实任务；再让 Codex 改一个属于自己的动作或角色场景。

## 节目钩子

开场不要先讲安装，也不要展示代码。先让伴侣用任务完成视频打断你：

> “我刚刚只是让 Codex 修完一个问题，它居然叫出了一个女朋友来给我庆祝。”

紧接着快速展示四个反差动作：

1. 小头像安静待机；
2. 双击进入厨房或雨夜场景；
3. 快速甩动产生声音反馈；
4. 一个真实 Codex 任务完成后自动展开庆祝。

屏幕大字：

> Codex 不只写代码，也能给自己做一个“有情绪的完成按钮”。

## 完整时间线与主持人口播

### 00:00–00:35 冷开场：先展示结果

画面：Codex 最后一条任务完成；右下角小头像展开并播放 `companion-event-task_complete.mov`。

口播：

> 这是我最近给 Codex 加的一个东西。它不是聊天机器人，也不会监听麦克风。Codex 真正做完任务之后，她才会出来庆祝；我工作太久，她会提醒喝水；无聊的时候，还能拖她、甩她、和她玩小游戏。今天我不只给你看效果，我会把安装包和完整提示词都给出来。

### 00:35–01:20 问题：为什么要做它

画面：普通 Codex 完成页，与伴侣反馈并排。

口播：

> AI 写代码越来越快，但任务完成往往只是多了一行文字。我们每天和智能体一起工作几个小时，却几乎没有仪式感。所以我想做的不是另一个对话框，而是一个独立的桌面角色：平时安静，真正需要反馈的时候才出现。

屏幕文字只保留三个词：

> 安静陪伴 / 即时奖励 / 可被改造

### 01:20–02:25 五层结构：一张图讲明白

画面依次出现五层，不展示大段代码：

1. Codex：理解目标、写代码、运行检查；
2. Seedance：生成角色母片、动作片和原生音画；
3. TTS：给拖拽、提醒和纯声音模式准备短音频；
4. SwiftUI：负责透明窗口、三种形态、交互和调度；
5. 完成事件桥：只在主任务真的完成时庆祝。

口播：

> Codex 是总导演；Seedance 负责表演；TTS 负责大量短反馈；SwiftUI 把它们变成一个真正的 Mac 应用；最后这一层最重要——任务完成不能靠猜，更不能每次 Codex 停下来都说完成，而要有一个明确、隐私最小化的完成事件。

### 02:25–04:15 三分钟安装

画面：下载并解压 `Chengyin-Companion-…-macos-arm64-preview.zip`。

操作：

1. 打开 `START-HERE.md`；
2. 双击 `Install Chengyin Companion.command`；
3. 展示安装成功的三行结果；
4. 打开 `~/Applications/Chengyin Companion.app`；
5. 双击 `Diagnose Chengyin Companion.command`；
6. 展示 Codex 的全局规则，但不要滚动显示其他用户指令。

口播：

> 这个包默认安装到你自己的 Applications，不需要管理员密码。它不会碰 Codex 的 config.toml，也不会抢占你已有的 notify。它只在 AGENTS.md 里加入一段带起止标记的规则，卸载时可以准确移除。

必须说明：

> 现在是 Apple Silicon、macOS 14 以上的个人预览包，使用本地签名，还不是经过 Apple 公证的公开正式版。

### 04:15–05:35 30 秒学会全部基本操作

按以下顺序现场演示：

1. `Command + Shift + M` 切换小头像、半身、全屏；
2. 单击；
3. 双击；
4. 长按再松手；
5. 拖动并快速甩向边缘；
6. 右键打开“逗她玩”；
7. 启动“抓住我”或“投喂时刻”。

口播：

> 我刻意没有做输入框。角色的价值不是逼你继续聊，而是在不打断工作的前提下，给完成、提醒和游戏一个更强的反馈。

### 05:35–08:05 素材是怎么做出来的

#### 05:35–06:15 先做角色合同，不要先批量烧 Tokens

画面：展示角色 Bible 的简化表格。

口播：

> 第一步不是写“生成一个美女”，而是把角色当成产品：明确成年原创身份、脸型、发型、身材比例、服装范围、颜色、镜头距离、语气和不能出现的东西。不要模仿明星，也不要拿可识别真人直接做商业角色。

#### 06:15–07:05 母片 + 派生片

画面：`companion-master-landscape.mov`，随后九个 `companion-action-*.mov` 快速切换。

口播：

> 为了省钱和保持一致，我先做一条角色母片。后面的喝水、伸展、鼓掌、跳跃、转圈、大笑、比心、飞吻和加油，都尽量以母片作为视频输入生成。这样既比每次从零生成便宜，也更容易保持同一个人。

#### 07:05–07:35 原生音画与 TTS 分工

画面：有 AAC 音轨的动作片，对比纯 TTS 的拖拽短反馈。

口播：

> 关键表演用 Seedance 原生音画，让口型、动作、笑声和环境声一起生成。大量只有一两秒的拖拽反馈和健康提醒，则提前用 TTS 做成素材，运行时直接播放，不占云端算力。

#### 07:35–08:05 素材命名就是接口

画面：资源目录文件名和 `Models.swift` 的动作枚举并排。

口播：

> 这里有一个特别适合 Codex 的技巧：命名要稳定。动作 0 到 8、场景名、事件名就是代码和素材之间的合同。Codex 可以检查每段视频的尺寸、时长、音轨和首帧，再自动接到对应行为。

### 08:05–10:15 一条长提示词让 Codex 自己推进

画面：打开 `03-CODEX-MASTER-PROMPT.md`，整段复制到新 Codex 任务。

口播：

> 如果要让观众真正复现，我不建议他照着视频敲几十条命令。更适合智能体的方式，是把目标、边界、阶段、验证和停止条件一次说清楚。Codex 会先盘点，再列计划，然后一阶段一阶段完成。

屏幕录制重点：

- Codex 先读取项目说明，而不是立刻改代码；
- 它识别“快速安装”还是“源码改造”；
- 涉及 Seedance 付费调用时停止等待确认；
- 测试事件进入临时目录；
- doctor 通过并真实安装后，才触发一次完成庆祝。

### 10:15–11:50 现场改一个小玩法

推荐演示题：新增“番茄钟结束后的击掌奖励”，不要现场换整个人物。

给 Codex 的短追加指令：

> 在现有伴侣上增加一个 25 分钟专注计时器。计时中保持小头像安静；结束后自动展开到半身，播放鼓掌视频和一条不重复的鼓励语；允许暂停和取消；不得把计时器结束伪装成 Codex 任务完成；增加自动检查并安装验证。

口播：

> 先改一个闭环，比一开始重做整个角色更容易成功。输入、即时反馈、奖励、冷却、自动测试，这五件事齐了，就是一个完整玩法。

### 11:50–12:55 三个最容易踩的坑

1. **把 turn ended 当 task completed**：Codex 每次停下来不等于任务真的完成。
2. **批量生成前没有母片**：角色会漂、成本也会上升。
3. **安装包只在自己电脑上能跑**：必须在隔离 HOME 中测试安装、AGENTS 合并、诊断和事件桥。

### 12:55–13:45 成本、隐私和权利

口播：

> 应用运行时不需要把屏幕、代码、Prompt 或对话发出去，也不申请麦克风权限。视频和短语都可以预生成、本地播放。真正要公开分发时，还要解决角色、声音、音乐和字体权利，以及 Developer ID 签名和 Apple 公证。节目里展示的 Seedance 价格也必须以录制当天官方页面为准。

### 13:45–14:20 结尾与 CTA

画面：运行一个很小但真实的 Codex 修改任务；完成事件触发结尾庆祝。

口播：

> 安装包让你先玩起来，源码包让 Codex 继续把她变成你自己的版本。你最想给自己的 Codex 加什么反馈？是完成任务跳舞、深夜催你睡觉，还是一个完全不同的角色？把玩法告诉 Codex，从一个小闭环开始。

屏幕 CTA：

> 下载预览包 → 完成一个真实任务 → 改造一个属于你的玩法

## 节奏纪律

- 每 20–35 秒至少出现一次结果、动作、目录或流程变化。
- 单次代码画面不超过 12 秒；只高亮与当前讲解有关的 3–8 行。
- 不朗读文件名和命令全文；让字幕承担精确文本，主持人解释为什么。
- 伴侣一共主动“打断”主持人三次：冷开场、玩法演示、片尾完成。更多会显得喧宾夺主。
- Seedance 素材只展示生成结果、Prompt 结构和成本台账，不在节目里暴露 Key、完整账号页或私人 TOS 地址。
