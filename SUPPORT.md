# Support

[简体中文](SUPPORT.zh-Hans.md) · English

## Before opening an issue

1. Run `./scripts/doctor.sh`. In the app, Settings → Support and Diagnostics can
   also copy a local privacy-minimal report for an issue.
2. Confirm whether the problem also happens with the built-in Starter assets.
3. Remove secrets, user names, paths, prompts, source code and task contents from the
   report.
4. Search existing issues and the troubleshooting documentation.

## Where to ask

- Reproducible bug: use the bug report issue template.
- Feature or new interaction: use the feature request template.
- Security, privacy or rights problem: follow `SECURITY.en.md` privately.
- General usage or pack-authoring question: use GitHub Discussions after the public
  repository is created.

The project currently provides community support without guaranteed response times.
Do not send API keys, payment data, certificates, private media or full diagnostic
archives through a public issue.

The in-app text report is never uploaded automatically and deliberately excludes
user names, paths, task text, prompts, source code, event history, relationship
memory and pack identifiers. Review it before posting, just as you would any text.
