# 已有素材如何讲成清晰教程

节目不需要重新生成素材；把现有结果讲成四个可复制的生产步骤。

## 步骤一：角色母片

演示素材：`companion-master-landscape.mov`。

要讲清的 Prompt 结构，而不是展示一个神秘“咒语”：

1. **角色锚点**：原创虚构成年人（25+）、脸型、发型、身材比例；
2. **造型锚点**：服装类别、主色、材质、妆容；
3. **镜头锚点**：16:9、中景、正面/三分之二角度、留出头像中心裁切区域；
4. **动作锚点**：自然呼吸、眨眼、微笑、轻微重心移动；
5. **声音锚点**：是否说话、语言、台词、环境声；
6. **禁止项**：真人/明星相似、年龄模糊、身份漂移、手指错误、字幕、水印、镜头跳变。

给 Codex 的示范指令：

```text
为一个 macOS Codex 桌面伴侣设计一条 16:9 角色母片合同。角色必须是原创虚构成年人 25+；列出固定身份锚点、造型、镜头、自然小动作、中心裁切安全区、原生音轨策略、禁止项和人工验收表。先只写合同和 Prompt，不调用生成 API。
```

## 步骤二：母片派生九种动作

演示素材：`companion-action-0.mov` 到 `companion-action-8.mov`。

| 编号 | 动作 | 教程中强调的动作合同 |
|---|---|---|
| 0 | 喝水 | 杯子接触嘴部自然，台词和吞咽节奏不冲突 |
| 1 | 伸展 | 全身重心连续，避免只晃静态图片 |
| 2 | 鼓掌 | 双手接触、掌声音效与动作同步 |
| 3 | 跳跃 | 起跳、腾空、落地完整，落地声同步 |
| 4 | 转圈 | 身份和服装在背面不漂移 |
| 5 | 大笑 | 面部、肩膀和呼吸一起变化 |
| 6 | 比心 | 手势清晰，手指结构稳定 |
| 7 | 飞吻 | 手到嘴、停顿、向镜头送出三段动作 |
| 8 | 加油 | 眼神看镜头，动作有明确结束姿势 |

给 Codex 的示范指令：

```text
基于已经通过审核的角色母片，规划九条 4 秒互动派生片：喝水、伸展、鼓掌、跳跃、转圈、大笑、比心、飞吻、加油。每条写独立 Prompt、动作起承转合、原生台词/音效、首尾帧、身份一致性检查和拒绝条件；优先含视频输入路线。先估算资源包 Tokens，等我确认后再调用。
```

## 步骤三：关键表演用原生音画，短反馈用 TTS

现有结果：

- 9 条手动动作和任务完成片：1280×720、约 4.096 秒、H.264 + AAC；
- 4 条迷你生活场景：640×640、约 4.096 秒、H.264 + AAC；
- 4 条动态小头像：232×232、约 4.042 秒、静音循环；
- 159 条预生成短语：用于提醒、拖拽、小游戏和纯声音模式。

给 Codex 的示范指令：

```text
把伴侣声音分成两层：关键表演使用视频模型原生音画；1–3 秒的拖拽、提醒、小游戏反馈使用预生成 TTS。输出事件分类表、台词长度上限、文件命名、响度目标、避免重复策略和 ffprobe/清单校验，不申请麦克风权限。
```

## 步骤四：用稳定文件名接入代码

素材与代码的核心映射：

```text
CompanionAction.drink = 0  → companion-action-0.mov
CompanionAction.stretch = 1 → companion-action-1.mov
...
task_complete → companion-event-task_complete.mov
```

给 Codex 的示范指令：

```text
扫描 Resources 中的 mov 和 voice-lines.json，与 Swift 枚举逐项核对。报告缺失、重复、错误尺寸、无音轨、首帧不可见和未被代码引用的素材；修复映射后运行媒体解码、声音清单和完整 doctor。测试完成事件必须使用临时 CHENGYIN_EVENT_ROOT。
```

## 节目中不要展示的内容

- 火山引擎 API Key、TOS 签名地址、账号余额明细；
- 可识别真人参考照片；
- Codex 会话正文、私人项目名、代码和本机私人路径；
- 尚未复核权利却宣称“可商用”的素材；
- 用预览快捷键冒充真实任务完成。
