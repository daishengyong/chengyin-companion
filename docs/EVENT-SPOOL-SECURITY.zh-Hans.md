# Companion Event 收件箱安全

[English](EVENT-SPOOL-SECURITY.md)

本契约覆盖受信任适配器写出隐私最小化 Companion Event 后，由澄音读取的本地
收件箱。它避免损坏或恶意的本地条目被误判成任务完成、触发无界扫描或形成隐私
泄漏；它不增加网络传输，也不扩大 App Server 的“完成”语义。

## 可接受条目契约

- 收件箱根必须属于当前用户且权限严格为 `0700`；最终路径组件以目录和 no-follow
  语义打开。
- 事件必须是属于当前用户、只有一个硬链接、权限为 `0600` 的普通文件，文件名为
  `<UUID>.json`；解码后事件内 UUID 必须与文件名一致。
- 读取通过已经打开的目录描述符执行，并受 Companion Event 载荷上限约束。软链接、
  FIFO、宽松权限、空文件／超大文件、损坏事件及文件名与内容不一致都会被忽略。
- 不认识的不安全条目会被保留，不会被跟随或删除。
- 监听器启动前已经存在的安全事件只建立去重基线，不会重播；启动后的新事件仍精确交付一次。
- 终态语义由独立 Core 生产者／版本策略判定；文件本身合法但来源未登记时只能成为回复就绪。
- 信封解码、有界时长和不透明任务引用清洗归无能力的 `CompanionEventIngress.swift` 所有；
  监听器只拥有传输、跨重启基线、去重与健康状态。边界门禁止隐私投影重新并回监听器，也禁止
  ingress 获得文件系统、网络或进程能力。

## 上限与保留

单次扫描最多查看 4,096 个目录条目，最多保留 512 个安全事件文件；只清理经过
验证、超过 36 小时或超出保留上限的安全文件。目录过载时返回稳定状态码
`EVENT_SPOOL_ENTRY_LIMIT_EXCEEDED`，并且不会删除未知条目。

## 实时健康与恢复

监听器每轮都报告根目录健康，而不是只在启动时检查。由正常转为不安全时只产生一
次不含内容的“集成断开”信号；本地安全修复成功后只产生一次“集成恢复”信号。
点击、小游戏、本地媒体与周期关怀仍然可用。诊断只显示稳定状态码，不包含用户名、
事件路径、任务正文、提示词或上游标识。修复只创建或恢复应用自有目录，不覆盖未知
条目。

## 威胁边界

本实现防护意外链接、简单文件替换、宽松权限、损坏输入、陈旧堆积与普通本地故障。
它不是来源认证，也不声称能对抗以同一用户身份运行、可竞态修改文件系统调用，或能
同时修改事件与本地证据的主动进程。该模块也不认证中间父目录。更强边界需要单独
设计带认证的传输或操作系统隔离。

## 验证

```bash
./scripts/run-event-spool-smoke.sh
python3 scripts/check-event-spool-integration.py
```

烟测只使用临时目录，覆盖合法交付、未变更与跨重启去重、启动后新事件精确一次交付、
未登记生产者降级、软链接／硬链接／FIFO／权限／大小
拒绝、安全的过期与容量清理、过载行为、路径安全错误码，以及运行中损坏与修复转换。
集成检查与 Core 边界门还会拒绝缺失 ingress、投影重新合并、ingress 获得禁用能力以及监听器
绕过委托。这些只是源码 token 防回退门，不是编译器 AST 证明或主动攻击认证。

## 发行边界

通过这些检查只支持本地工程预览与可克隆／可贡献声明。媒体权利、最终许可证、正式
维护者身份、Developer ID 签名、公证、干净 Mac 检查和所有者批准没有分别完成前，
产物仍是 `NOT_PUBLIC_RELEASE_READY`。
