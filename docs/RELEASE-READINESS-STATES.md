# 发行就绪状态与人工所有者门

Chengyin 使用七个互不替代的状态。任何工具、README、CI 或界面都不得把前一状态
自动升级为后一状态。

| 状态 | 含义 | 当前自动证据 |
| --- | --- | --- |
| 工程可安装 | 本地 `.app` 结构完整，包含主程序、Info.plist 和事件助手 | 构建与 doctor |
| 个人预览 | 本地应用通过完整性签名校验，可供所有者在自己的 Mac 上预览 | ad-hoc 签名与本地安装验证 |
| 媒体权利通过 | 拟发布媒体的来源、授权、成年/虚构、无障碍和人工审阅均有证据 | Content Pack v2 与内置 Starter 契约会核对字段、文件哈希、回退和审阅声明；最终权利结论仍需人工 |
| 最终 LICENSE | 代码、Starter 媒体、品牌和第三方通知的最终文本已由所有者批准 | 人工所有者门 |
| Developer ID 签名 | 发行产物由有效的 Developer ID Application 证书签名 | 对最终产物检查签名 Authority；ad-hoc 不算 |
| Apple 公证 | 最终签名产物已被 Apple 接受并固定公证票据 | 人工提交和产物证据门 |
| 公开发行批准 | 所有者核对发行版本、权利范围、支持承诺和渠道后明确批准 | 人工所有者门 |

只有七项全部为真时，机器回执的 `publicReleaseReady` 才能为 `true`。当前项目明确是
“工程可安装 / 个人预览”阶段；媒体权利、最终许可证、Developer ID、公证和公开批准仍为
待完成，因此不得宣称公开发行就绪。

## 机器可读回执

运行：

```bash
./scripts/release-readiness-audit.py --json
```

回执只包含构建身份、布尔状态和稳定状态名，不包含用户名或绝对路径。即使工程构建和
个人预览通过，只要一个发行门未完成，状态仍是 `NOT_PUBLIC_RELEASE_READY`。

人工门记录在 `release/release-gates.json`。更新这些状态必须附上不含秘密或个人信息的
证据引用，并由项目所有者作出真实决定。自动化不得选择许可证、代替法律/权利审阅、申请
证书、提交公证或批准公开发布。

## 对外用语

当前可以说：

> 可从源码构建并进行本地个人预览；Content Pack v2 的贡献契约和安全校验已自动化。

当前不能说：

> 已签名公证、媒体权利已全部通过、最终开源许可证已生效、可公开发行或可收费。

便携包文件名中的 `preview` 也是契约的一部分；在所有门完成前不得去掉。

内置 Starter 的机器回执目前是 `PASS_WITH_PENDING / INTERNAL_PREVIEW_ONLY`：198 个文件
都在清单中，0 个完成权利审阅，3 个数据或本地化文件的无障碍状态为不适用。详见
[Starter 素材契约](STARTER-MEDIA-CONTRACT.zh-Hans.md)。文件哈希通过只证明当前包内一致，
不证明来源真实性或自动授予发行权。
