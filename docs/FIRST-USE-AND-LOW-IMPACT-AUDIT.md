# 新 Mac 首次使用与低动态效果审计

本审计回答两个独立问题：一台未配置生成服务的新 Mac 能否从源码安全启动，
以及担心 GPU、发热或动态效果的用户能否保持基本陪伴功能。它不等同于正式发行认证。

## 审计范围与结论

| 路径 | 已验证行为 | 未由本审计证明 |
| --- | --- | --- |
| 新 Mac 源码安装 | Apple Silicon、macOS 14+、Command Line Tools、Swift、Python 3.9+、2 GB 可用空间和 `/Applications` 写入能力会在构建前检查 | Intel Mac、macOS 13 或更早版本 |
| 首次使用隐私 | 安装路径不调用 Seedance/TTS，不读取 API Key，不修改 Codex 配置，不申请麦克风，不创建账户，不上传诊断；快速上手只保存合约版本与一个本机节奏偏好 | 用户以后主动运行素材生成脚本的行为 |
| 低动态／低 GPU | 停止空闲循环视频与媒体体验，禁用界面过渡，强制预生成声音模式，并使用轻量 sprite 待机 | 精确功耗、温度、帧率或不同 Mac 型号的实验室基准 |
| macOS“减少动态效果” | 禁用界面过渡，尊重系统无障碍偏好 | 它不会自动等同于应用的低 GPU 模式；用户仍可单独保留视频 |
| macOS 展示无障碍 | “减少透明度”把影院外观降为不使用材质的柔暗外观，“增强对比度”提高衬底强度 | 人工视觉对比与色觉辅助技术认证 |
| 中英无障碍语义 | 头像、播放模式、魔术棒面板、完成回应、惊喜和安全修复使用语义键与稳定控件标识；英文值不得残留中文，格式占位符必须一致 | VoiceOver 实机朗读顺序、焦点移动和发音质量认证 |
| 多显示器恢复 | 指定屏幕断开后依次回到当前、主屏、第一块有效屏或安全默认画布，窗口坐标重新收敛到可见区域 | 当前单屏开发机不能证明真实双显示器视觉效果 |
| 恢复 | 关闭低动态模式可恢复标准动态；选择“音画同步”会显式退出低动态模式；设置可备份和恢复 | 损坏操作系统或硬件故障恢复 |

源码已通过自动化策略检查和当前开发机验证；尚未在一台物理“刚开箱”Mac 上执行
Gatekeeper 首次下载路径。因此准确表述是“工程可安装、个人预览可验证”，不是
“已签名、公证、公开发行就绪”。

## 首次使用路径

1. 安装 Apple 的 Command Line Tools：`xcode-select --install`。
2. 确认 Python 版本不低于 3.9；预检会执行真实探针，而不是只判断是否存在名为 `python3` 的命令。
3. 获取仓库后，在仓库根目录运行 `./scripts/bootstrap-local.sh --check-only`。
4. 所有预检通过后运行 `./scripts/bootstrap-local.sh`。
5. 安装器会验证合约和示例内容包、构建应用、事务式替换本地应用并执行 doctor。
6. Codex 任务通知保持未启用；只有用户查看精确配置并主动确认后才会配置。

干净安装首次打开后会展示一个可跳过的本机快速上手：先轻点、再双击、只选择“陪我工作／偶尔逗玩／温柔提醒”中的一个节奏，随后运行一次模拟 Codex 工作弧。进度节点只显示“工作中”，只有模拟终点才进入完成庆祝。三分钟后不会停止、降级或出现付费墙；既有用户升级时不会被强制打断，可从魔术棒面板显式重播。该闭环可用 `python3 scripts/check-first-session-integration.py` 与 `./scripts/run-first-session-runtime-coordinator-smoke.sh` 离线复验。

检查阶段是只读的；不会提前构建、安装或修改用户配置。如果检查失败，应先执行终端给出的
恢复动作，而不是跳过系统安全机制。

在自动化环境明确禁止任何新增授权时，可运行
`./scripts/run-first-use-low-impact-audit.sh --zero-authorization`。该模式仍检查系统、工具链、
仓库、隐私边界、低动态策略和窗口策略，但不探测或修改 `/Applications`，也不启动 GUI；
结果必须是 `PASS_WITH_PENDING`，并把本地应用替换与屏幕窗口复核保留为所有者门。它不是
严格安装预检的替代品。

小头像点击、魔术棒选择和游戏胜利的真实弹出／回收可用
`python3 scripts/audit-direct-play-runtime.py` 单独验证。该门只接受一个身份匹配的当前应用；
若本机 GUI 已锁屏，回执为 `PENDING`、错误码为 `UI_DIRECT_PLAY_GUI_SESSION_LOCKED`，不得
误报为产品失败或自动申请指针权限。解锁后重跑，才可把真实画面链路记为通过。
六游戏奖励聚合门使用同一三态规则：锁屏时退出码为 2、`proofKind=NO_GUI_PROOF`、
已验证游戏数为 0，不能携带任何展开／回收证明；只有解锁后六项全部通过才允许 `PASS`。

## 低动态／低 GPU 路径

在应用“设置 → 声音”打开“低动态／低 GPU 模式”后：

- 当前视频或声明式内容序列立即停止；
- 空闲头像和半身改用轻量 sprite，不再创建循环视频播放器；
- 手动动作、生活场景、任务提醒和周期关心保留预生成声音反馈，但不启动视频体验；
- SwiftUI 的展示与媒体切换动画关闭；
- 头像／半身／舞台之间的 AppKit 窗口尺寸切换动画也关闭；
- 换显示器、屏幕空间缩小或保存坐标异常时，窗口由共享纯策略重新限制在可见区域；
- 全屏 16:9 舞台尺寸来自策略选中的显示器，而不是无条件读取主屏；
- 该偏好进入便携设置备份和隐私最小诊断，旧备份安全默认为关闭；
- 用户切回“音画同步”时会显式退出低动态模式，避免界面声称低负载而后台恢复视频。

`CompanionPerformancePolicy` 是 UI、播放和契约测试共享的纯策略源。CI 必须验证：
低动态时 `effectivePlayback == audioOnly`、循环媒体和视频体验均不允许、动画过渡关闭。

## 人工硬件抽查清单

在对外提供二进制之前，所有者仍需在一台未安装开发版的 Apple Silicon Mac 上完成：

- 从 GitHub 下载或克隆后的 Gatekeeper 行为记录；
- 标准动态与低动态各运行 30 分钟，对比 Activity Monitor 的 CPU、GPU、内存和能耗；
- 睡眠/唤醒、拔插显示器、低电量和“减少动态效果”切换；
- 在两块尺寸和缩放不同的显示器间分别验证跟随窗口、固定主屏和指定屏幕，并确认拔线后自动回退；
- 开启低动态后确认没有视频音轨、后台播放器或持续窗口动画；
- 删除应用与本地数据的恢复说明核对。

这些结果应记录硬件型号、macOS 版本、应用构建身份和观测方法。未完成前不得把本文件
当作低功耗认证或公开发行证明。

源码级中英无障碍契约可用
`python3 scripts/audit-accessibility-localization.py --json` 检查；负向矩阵由
`./scripts/run-accessibility-localization-smoke.sh` 验证。其回执明确标为
`source-and-bundled-copy-contract-not-runtime-voiceover-certification`：它能阻止缺键、英文残留中文、
硬编码关键语义与控件标识丢失，但不能替代英文系统下的真实 VoiceOver 和干净 Mac 视觉走查。

可重复的隔离英文走查由
`./scripts/run-english-first-use-visual-audit.sh` 生成五张当前运行窗口截图与路径安全回执，
并由 `./scripts/run-english-first-use-visual-audit-smoke.sh` 验证负向路径。证据边界与人工门详见
[英文首次使用视觉审计](ENGLISH-FIRST-USE-VISUAL-AUDIT.zh-Hans.md)。物理干净 Mac 和人工
VoiceOver 仍保持待验证，不因隔离实验通过而自动关闭。

安装后的窗口存在性可用 `./scripts/run-window-presence-audit.sh` 做只读抽查。回执只报告
Chengyin 自己的可见窗口数量、尺寸、层级和透明度，不输出其他应用窗口标题或内容；它不能
替代对人物、裁切、文字和交互的人工视觉评审。
